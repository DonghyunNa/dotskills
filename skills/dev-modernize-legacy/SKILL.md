# dev-modernize-legacy

## 무엇을 하는가

레거시 모듈/서비스/리포지토리를 받아 **6개 산출물이 박힌 의사결정 가능한 전략 문서**를 만든다.

1. 인테이크 요약 — 합의된 범위·동기·제약·성공 정의·리스크 허용도
2. 진단 리포트 — 객관적 지표 7개 축
3. 후보 전략 3~5개 — 카탈로그에서 사례별 큐레이션
4. 위험-효과 매트릭스 — 같은 5축으로 후보 비교
5. 단계별 실행 계획 — Phase 1 = 안전망
6. 롤백 신호 — 측정 가능한 임계값

## 언제 호출되나

- 큰 모듈/서비스를 *조금씩* 바꿔야 할 때 ("저 부분 손대고 싶은데 무서워")
- 의사결정자에게 옵션을 제시해야 할 때 (rewrite vs refactor vs leave-alone)
- 기술부채 우선순위 회의 자료 준비
- 구체 패턴 자문 ("여기 strangler fig 어떻게 적용?")

## 언제 호출하지 않나

- 한두 시간이면 끝날 국소 리팩토링 — 그냥 한다
- 그린필드 새 프로젝트
- 단일 함수 이름 변경·타입 보강
- 이미 합의된 마이그레이션의 실행 단계 — `task-breakdown` 만 호출

## 작업 절차

### 1. 인테이크 — 5가지가 명확해질 때까지

| 항목 | 묻는 것 |
|---|---|
| 대상 범위 | 어떤 모듈/서비스? 경계가 어디? |
| 동기 | 왜 *지금*? (incident? 성능? 채용? 기능 막힘? 컴플라이언스?) |
| 제약 | 시간·인력·운영 중인지·downtime 허용도·외부 의존 |
| 성공 정의 | 6개월~1년 뒤 무엇이 *관찰 가능*해야 성공? |
| 리스크 허용도 | 한 번에 큰 변화 vs 점진적, prod 영향 어디까지? |

답이 흐릿한 항목은 *추측하지 말고* §6 출력의 `Open` 섹션에 그대로 남긴다.

### 2. 진단 — 7축 *병렬* 탐색

코드를 7개 축으로 동시 스캔. 각 축의 정의·측정 명령은:

→ **`references/diagnosis-axes.md`** 참고

축: hotspot · 테스트 커버리지 · 결합도 · 외부 통합 · 알려진 이슈 영역 · 빌드·배포 사이클 · 도메인 경계

직접 측정 가능하면 Bash/Read/Grep 으로 측정, 측정 불가하면 사용자에게 데이터 입력 요청. 추측 채움 금지.

### 3. 옵션 도출 — 카탈로그 큐레이션

8개 패턴 중 *이 사례에 적용 가능한 3~5개*만 골라 후보로. 8개 다 나열하면 큐레이션 안 한 것.

→ **`references/strategy-catalog.md`** 참고

각 후보마다 "이 사례에 왜 적합/부적합" 1~2 문장. 큐레이션 기준은 카탈로그 끝의 "큐레이션 가이드" 섹션.

### 4. 평가 — 위험-효과 매트릭스

후보를 *같은 5축* 으로 평가:

| 축 | 측정 |
|---|---|
| 효과 | 6개월 후 §1 성공 정의 충족도 (높/중/낮) |
| 시간 | 1주 / 1달 / 분기 / 반기+ |
| 리스크 | prod 장애·데이터 손상 가능성 |
| 의존 | 외부 팀·툴·예산 필요 여부 |
| 되돌리기 | 망쳤을 때 롤백 비용 |

### 5. 분해 — `task-breakdown` 위임

추천 전략을 [[task-breakdown]] 으로 Phase / Atomic task / Done-when 구조로 분해. 같은 repo 의 스킬이라 트리거 됨.

**Phase 1은 거의 항상 안전망**:
- 테스트 없으면 → characterization tests + 핵심 시나리오 통합 테스트
- 모니터링 없으면 → 핵심 지표(에러율·지연·사용량) 계측 + 알림
- 롤백 경로 없으면 → feature flag + DB 마이그레이션 reverse 가능성 점검

> 안전망 없이 진입 = 그 다음 사고 보고서를 미리 쓰는 것.

### 6. 롤백 신호 — *측정 가능*한 형태로 3~5개

| 좋은 신호 | 나쁜 신호 |
|---|---|
| 에러율이 baseline 대비 5% 초과 | "느낌이 안 좋다" |
| P95 응답시간 800ms 초과 | "테스트가 깨질 것 같다" |
| 같은 종류 incident 가 7일 안에 2건 | "팀이 불안해한다" |

각 신호마다 *대응 액션* 도 함께 (flag off, Phase 보류, §3 옵션 재평가 등).

## 안티 패턴

- ❌ §1 인테이크 건너뛰기 — "왜?" 모르면 옵션 평가 불가
- ❌ §2 진단 데이터 없이 옵션 던지기 — 추천 신뢰도 0
- ❌ Phase 1이 안전망이 아닌 것으로 시작 — 사고 보고서 예약
- ❌ Big Bang 을 default 추천 — 명시적·정량 근거 없이는 거의 항상 틀림
- ❌ "현대화" 가 사실 "내 취향 스택으로 다시 짜기" — §1 동기 진위 검증
- ❌ 카탈로그 8개 전부 나열 — 큐레이션 안 한 것
- ❌ 롤백 신호가 "느낌" — 임계값 없으면 신호가 아님

## 다른 스킬과의 관계

- [[task-breakdown]] (같은 repo) — §5 실행 계획 분해 위임. 호출 자동 트리거.

이 스킬은 외부 스킬/에이전트에 의존하지 않는다. 인테이크 질문·코드 탐색·계획 분해 모두 Claude 의 기본 능력 + 같은 repo 의 `task-breakdown` 만으로 수행.
